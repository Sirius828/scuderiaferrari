# Offset 计算区域调整说明

## 📋 修改概述

将 offset 计算的数据来源从**图像下半部分（50%~100%）**调整为**图像底部 20%（80%~100%）**。

---

## ✅ 修改内容

### 1. **Offset 计算区域调整**

**文件**: `perception_decision_node.py`  
**位置**: 第 459-470 行

#### 修改前
```python
# 计算偏移
half_h = h // 2
bottom_seg = mask_for_offset[half_h:h, :]  # y = 50% ~ 100%
center_offset = self._calculate_center_offset(bottom_seg)
```

#### 修改后
```python
# 计算偏移（使用图像底部 20% 区域）
y_start = int(h * 0.8)  # 从 80% 高度开始
bottom_seg = mask_for_offset[y_start:h, :]  # y = 80% ~ 100%
center_offset = self._calculate_center_offset(bottom_seg)
```

---

### 2. **分支掩码应用区域同步调整**

**文件**: `perception_decision_node.py`  
**方法**: `apply_branch_mask_for_offset`  
**位置**: 第 570-578 行

#### 修改前
```python
def apply_branch_mask_for_offset(self, road_mask, target_side):
    """应用分支掩码（增强版 - 覆盖整个下半部分）"""
    h, w = road_mask.shape
    masked = road_mask.copy()
    
    # 从图像中线开始屏蔽
    y0 = h // 2  # y = 50%
    y1 = h
```

#### 修改后
```python
def apply_branch_mask_for_offset(self, road_mask, target_side):
    """应用分支掩码（增强版 - 覆盖 offset 计算区域）"""
    h, w = road_mask.shape
    masked = road_mask.copy()
    
    # 从图像 80% 高度开始屏蔽，与 offset 计算区域一致
    y0 = int(h * 0.8)  # y = 80%
    y1 = h
```

---

## 🎯 修改原因

### 1. **更接近车辆的真实赛道信息**

- **80%~100% 区域**: 距离车辆最近，反映车辆当前所在位置的赛道
- **50%~80% 区域**: 距离车辆较远，可能受到透视变形影响更大

### 2. **减少远处干扰**

在以下场景中，上半部分可能包含干扰信息：
- **弯道**: 远处的赛道可能已经转弯，但近处还是直的
- **岔路口**: 远处的 Y 型分叉可能导致 offset 计算不准确
- **遮挡**: 远处的障碍物或噪声可能影响赛道检测

### 3. **提高响应速度**

- 使用更靠近车辆的信息，offset 变化更及时
- 车辆能更快响应赛道的变化

### 4. **与 near_roi 对齐**

当前配置：
```yaml
near_roi_y0_ratio: 0.77  # near ROI 从 77% 开始
near_roi_y1_ratio: 0.95  # near ROI 到 95% 结束
```

Offset 计算区域（80%~100%）与 near_roi（77%~95%）有较大的重叠，逻辑更一致。

## 💡 优势与注意事项

### ✅ 优势

1. **更精确**: 只使用最可靠的近处信息
2. **更快速**: 对赛道变化的响应更快
3. **更稳定**: 减少远处噪声和透视变形的影响
4. **更高效**: 计算区域更小，处理速度略快

### ⚠️ 注意事项

1. **数据量减少**: 
   - 从 240 行减少到 96 行（假设 h=480）
   - 如果近处赛道检测不稳定，可能导致 offset 波动

2. **需要确保近处赛道质量**:
   - 语义分割模型在近处的准确率必须高
   - 如果近处经常检测不到赛道，可能需要调整

3. **参数调优**:
   - 如果发现 offset 波动太大，可以考虑调整为 75%~100% 或 70%~100%
   - 如果发现响应太慢，可以保持 80%~100%

## 🔍 调试建议

### 1. **观察日志中的 offset 值**

```bash
ros2 topic echo /segmentation/center_offset
```

**正常情况**:
- 直道: offset 在 `-0.1 ~ +0.1` 之间小幅波动
- 弯道: offset 逐渐变化，平滑过渡
- 岔路: 在 LOCK 状态下，offset 应该明显偏向选定方向

**异常情况**:
- offset 频繁跳变（如从 -0.3 跳到 +0.3）→ 近处赛道检测不稳定
- offset 长时间为 0 → 近处没有检测到赛道

### 2. **检查 is_valid 标志**

```python
is_valid = bool(np.any(bottom_seg == 1))
```

如果 `is_valid` 经常为 `False`，说明近处经常检测不到赛道，可能需要：
- 降低 `y_start`（例如改为 0.75 或 0.70）
- 检查语义分割模型在近处的表现

### 3. **对比不同区域的 offset**

可以临时添加调试代码，对比不同区域的 offset：

|------|------------------|------------------|------|
| 行数 | 240 | 96 | ↓ 60% |
| 像素数 | 153,600 | 61,440 | ↓ 60% |

## 📝 总结

### 核心改动

1. **Offset 计算区域**: `50%~100%` → `80%~100%`
2. **分支掩码区域**: `50%~100%` → `80%~100%`
3. **两者保持一致**: 确保掩码完全覆盖 offset 计算区域

### 预期效果

- ✅ 更精确的赛道跟踪（基于近处信息）
- ✅ 更快的响应速度
- ✅ 更稳定的 offset 输出（减少远处干扰）
